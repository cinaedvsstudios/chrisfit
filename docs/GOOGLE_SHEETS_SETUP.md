# Google Sheets & Apps Script Backend

The ChrisFit web clone replaces the Android Room database with a cloud‑based
backend using **Google Sheets** as storage and **Google Apps Script** as
an API layer.  This document outlines how to set up the sheets, write
Apps Script endpoints and connect them to the web app.

## 1. Create a Google Sheets document

1. Visit [sheets.google.com](https://sheets.google.com) and create a new
   blank spreadsheet named **ChrisFit Data**.
2. Add four sheets (tabs) and rename them exactly as follows:
   * `entries`
   * `foods`
   * `weights`
   * `settings`
3. Populate the first row of each sheet with column headers matching the
   Room entities:

   **entries**

   | A | B      | C    | D        |
   |---|--------|------|----------|
   | id | date | name | calories |

   **foods**

   | A | B    | C       |
   |---|------|---------|
   | id | name | calories |

   **weights**

   | A | B    | C      |
   |---|------|--------|
   | id | value | date |

   **settings**

   | A | B             | C             | D   |
   |---|---------------|---------------|-----|
   | id | dailyCalories | dailyDeficit | bmr |

4. Leave the sheets empty.  IDs will be generated by the backend.

## 2. Apps Script project

1. Open the sheet, choose **Extensions → Apps Script** and create a new
   project.
2. In the script editor delete any default code and create a file named
   `Code.gs`.  Paste in the contents of `google-apps-script/Code.gs` from
   this repository.  That script implements endpoints for all CRUD
   operations and JSON import/export.  Review the comments in the
   script to understand each function.
3. Replace `SPREADSHEET_ID` at the top of the script with the ID of your
   spreadsheet (the long string in the URL between `/d/` and `/edit`).
4. Click **Deploy → New deployment**, select **Web app**, set an
   appropriate description, choose **Execute as Me** and **Allow anyone
   with the link**.  Deploy the app and copy the provided URL.  This
   will serve as your API endpoint.
5. (Optional) If you want to restrict access set a secret token in the
   script (see the `TOKEN` constant) and include it in your
   `js/config.js` file as `token: 'your-token'`.  Without a token the
   endpoint is publicly callable.

## 3. Configure the web app

1. Inside the `js/` folder of the web project create a new file
   `config.js` and export your configuration:

   ```js
   export const CONFIG = {
     baseUrl: 'https://script.google.com/macros/s/AKfycb.../exec',
     token: 'optional-shared-secret'
   };
   ```

2. The app will now read from and write to your Google Sheets.  When
   `baseUrl` is empty it operates in demo mode using in‑memory data.

## 4. Expected data flow

* **Reading data:** The frontend fetches settings, foods, entries and
  weights via GET requests.  The Apps Script functions read rows from
  the corresponding sheets, convert values to JSON and return them.
* **Writing data:** New records are appended to the bottom of the sheet
  with an incremented `id`.  Updates and deletes locate rows by `id` and
  modify or remove them.  Settings always occupy row 2 on the
  `settings` sheet.
* **Import/export:** Export returns a JSON object with three arrays
  (`entries`, `foods`, `weights`) matching the Android backup format.
  Import clears existing data and writes new rows based on the arrays.

See `Code.gs` for implementation details.  You can extend or secure the API
as needed but must preserve the field names and behaviours to remain
compatible with Android backups and the web app.
